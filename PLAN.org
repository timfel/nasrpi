 I want a set of setup (bash) script for my raspberry pi. All steps should be
 idempotent and not clobber existing settings, just check and potentially
 interactively update what's there. Probably the script should be split up, and
 we end up with:
 
 #+begin_src 
   01_establish_mount_points.sh
   02_setup_pizauth_mbsync_sendmail.sh
   03_setup_smartmontools.sh
   04_setup_rclone.sh
   05_setup_backup.sh
 #+end_src

01
   - ensure that i have disks by uuid in etc fstab that mount under
     * =/media/media=
     * =/media/media_backup=
     * =/media/nas=
     * =/media/nas_backup=
       + if they are not there, guide me by pointing out which disks i have,
         which names and sizes they have, asking me which of these i want
         where, then help preview edits to =/etc/fstab= and let me confirm
02
   - install pizauth (github.com/ltratt/pizauth), a rust oauth2 token daemon,
     built from a pinned tag into /opt/pizauth, with a /usr/local/bin/pizauth
     wrapper that pins the socket to /run/pizauth so the daemon, root's cron
     jobs and interactive shells all talk to one instance
   - add a systemd service that runs 'pizauth server' at boot
   - interactively add my accounts to /etc/pizauth.conf (gmail, outlook, ...);
     the oauth url opens in my laptop's browser through an ssh tunnel and
     pizauth catches the redirect itself, so nothing has to be pasted back
   - keep a dump of the token state so rebuilding the box does not mean signing
     in again. seal it with a key derived from the lan (fritzbox upnp device id),
     so the file is worthless off-site; there is no unsealed fallback at all --
     away from home the key cannot be derived, the dump stays sealed and pizauth
     comes back asking for a sign-in
   - install mbsync
   - setup =mbsync= config to pull (Sync Pull only) into
     =/media/nas/Mail/<MAILBOX>= with XOAUTH2 straight to the provider; folder
     names stay editable in =/etc/nasrpi-mailmaps=, =/etc/pizauth.conf= stays
     the account source of truth
   - add a cron job for mbsync *down only*, weekly, ask me for the time, and just
     skip (exit 0) when the NAS is not mounted or pizauth is not answering --
     missing one week is fine, the next run catches up
   - setup =sendmail= (msmtp + msmtp-mta) with =auth xoauth2= and the token from
     =passwordeval pizauth show <account>=, asking which upstream mailer system
     mail should come from
   - cleanup_emailproxy.sh: one-off removal of the python emailproxy install
     this replaced (service, /opt/emailproxy, its cron entry)

03
   - setup smartmontools to monitor all my disks, but make sure they do not
     spin up for SMART testing if they are currently idle. tell it to use
     =sendmail= to inform me when sometehing degrades
   - if smart data shows failure indicators (read errors or relocated sectors),
     unmount the failing drives
04
   - set up =rclone= and give me a chance to set up any remotes i need
   - set up a weekly cron job that syncs all remotes configured in rclone to
     =/media/nas/<REMOTENAME>=, ask me what time of day and what weekday it
     should run; should just skip if the target is not mounted
05
   - setup a weekly cron job that runs rsync backup from =/media/nas= to
     =/media/nas_backup= and from =/media/media= to =/media/media_backup=, ask
     me what time of day and what weekday it should run; should just skip if the
     target is not mounted; should skip if more than N% files would be deleted;
     it should =sendmail= a report if it failed in that case
