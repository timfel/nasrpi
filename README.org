* nasrpi setup scripts

Run them in order, as your normal user, on the Pi; they escalate with ~sudo~
exactly where root is needed:

#+begin_src sh
./01_establish_mount_points.sh
./02_setup_emailproxy_mbsync_sendmail.sh
./03_setup_smartmontools.sh
./04_setup_rclone.sh
./05_setup_backup.sh
#+end_src

Run any of them again any time: everything checks first, changes only what's
missing, and asks before touching anything. Shared helpers live in ~lib.sh~
(prompts, cron installer, package installer) — tweak there first.

** What each script does

*** 01 — Mount points

Puts your four disks into =/etc/fstab= (by UUID) at =/media/media=,
=/media/media_parity=, =/media/nas= and =/media/nas_backup=. Guides you through
picking disks by name/size, previews the fstab edit, and backs up fstab first.

*** 02 — emailproxy, mbsync, sendmail

- Installs ~uv~ + ~emailproxy~ under =/opt/emailproxy=, and creates a systemd
  service named ~emailproxy~ that runs ~=--no-gui~ at boot, pointed at
  =/opt/emailproxy/accounts.ini= via ~=--config-file~.
- Seeds that file in *emailproxy's own config format* (same format as the
  upstream =emailproxy.config= sample: accounts are =[you@example.com]= sections,
  local listeners come from =[IMAP-1993]= / =[SMTP-1587]= style sections) and
  opens it for you to add your Gmail / Outlook / ... accounts. Everything below
  is read from that file: account list, local ports, TLS mode
  (=02_emailproxy.py= does the ini parsing).
- Runs emailproxy's ~=--external-auth=~ OAuth flow whenever the account set
  changes: the service is stopped and emailproxy runs in the foreground (that
  mode needs a real terminal) and prompts for the OAuth URL and the pasted
  post-authentication URL itself, while 02 triggers one IMAP login per account —
  login accepted means the token is in place.
- Generates =/etc/mbsyncrc= to pull *down only* into
  =/media/nas/Mail/<MAILBOX>= (one folder per account, you name them), and
  installs a weekly mbsync cron job that skips when =/media/nas= is unmounted.
- Sets up *msmtp* (plus ~msmtp-mta~, which provides =/usr/sbin/sendmail=) so
  every script, smartd and cron job sends mail through =/etc/msmtprc= →
  emailproxy's local SMTP port (from its =[SMTP-<port>]= section, e.g.
  ~localhost:1587~) using the upstream mailer you pick.

*** 03 — smartmontools

- Installs smartmontools to monitor all disks *via =/dev/disk/by-uuid=*.
  Schedules short tests nightly and long tests weekly, but *never spins up
  spun-down disks* (=-d maint=).
- smartd sends alert mail itself; each alert also runs a =-M exec= handler:
  =/usr/local/bin/nasrpi-smartd-alert.sh=. The device is passed as an argument
  and the report arrives on stdin. The handler logs to
  =/var/log/nasrpi-smart-alert.log= and *unmounts the failing disk*
  (=AUTO_UNMOUNT= at its top).
- *Zero tolerance:* =-I 5 -I 187 -I 197 -I 198= sends mail and triggers the
  handler as soon as reallocated, uncorrected or pending sector counts change at
  all.

*** 04 — rclone

Installs rclone and runs ~rclone config~ so you can add remotes. Then installs a
weekly cron job that copies every remote into =/media/nas/<REMOTENAME>=. Skips
when =/media/nas= is unmounted.

*** 05 — Backup

Installs a weekly cron job running ~rsync -a --delete~ for two pairs:

- ~/media/nas/ → /media/nas_backup=~
- ~/media/media/ → /media/media_parity=~

Per pair it dry-runs first; if more than N% of destination files would be
deleted, it aborts that pair and *sends you a report*. Also mails on failure.
Skips a pair when either of its mounts is missing.

** Tweaking

- Cron schedules: rerun the script, or edit =/etc/cron.d/nasrpi-*= directly.
- Folder names for mail / remotes: =/opt/emailproxy/.nasrpi-mailmaps=,
  =/etc/nasrpi-rclone-maps= — plain ~name=folder~ files, edit freely.
- Backup knobs (~NOTIFY_EMAIL~, ~DELETE_PCT~): top of
  =/usr/local/bin/nasrpi-backup.sh=.
- SMART alert behaviour: ~AUTO_UNMOUNT~ at the top of
  =/usr/local/bin/nasrpi-smartd-alert.sh= (set ~no~ for log/mail only); watched
  attributes are the =-I= list in =/etc/smartd.conf= (zero tolerance by default).
  Rerun 03 after adding or removing disks.
- Backup source/dest pairs: ~PAIRS~ at the top of
  =/usr/local/bin/nasrpi-backup.sh~ (one ~source dest~ line per pair).

** Notes / gotchas

- Needs Debian/Raspbian (~apt~) on the Pi; scripts exit cleanly elsewhere.
- Config source of truth: =/opt/emailproxy/accounts.ini= (emailproxy's own ini
  format). Add an account section per address with =permission_url=,
  =token_url=, =oauth2_scope=, =client_id= (Outlook and Gmail examples are
  commented in the seeded file). Unconfigured sample sections that ship with
  emailproxy (=*** your client id here ***=) are detected and ignored. Rerun 02
  after edits to regenerate =/etc/mbsyncrc=, =/etc/msmtprc= and the cron jobs.
- The password 02 asks for is the *local* proxy login password: mbsync/msmtp use
  it to talk to emailproxy and emailproxy uses it to encrypt its cached OAuth
  tokens; the real provider authentication is OAuth in the browser. It is stored
  in =/etc/mbsyncrc= (=Pass ..., mode 600) and =/etc/msmtprc= so unattended sync
  and =sendmail= work.
- The proxy is only ever used over plain text on localhost (IMAP + SMTP, no
  local TLS, no POP): =mbsync= gets ~SSLType None~, msmtp gets ~tls off~; the
  proxy does all upstream TLS itself.
- OAuth: 02 offers the sign-in flow on every run — stop the service, run
  ~emailproxy --no-gui --external-auth~ in a second shell, and 02 triggers an
  IMAP login per account until it is accepted. Say no to the prompt when you
  know the tokens are fine. Catch-all accounts (=[@domain.com]=) are not
  enumerable; use one section per address.
- The local proxy password is **mandatory**: emailproxy aborts any login without
  one (=Login failed - no password provided for account ...=), so there is no
  ~auth off~ mode — msmtp is always written with ~auth on~.
- Outgoing mail always goes through msmtp (=~/etc/msmtprc~, mode 600) via the
  ~sendmail~ compatibility shim from ~msmtp-mta~. Beware: a =~/.msmtprc~=
  would override the system config for that user.
- 05's safety net compares proposed deletions against each destination's file
  count; the first run against an empty destination deletes nothing.

** Testing without the Pi

#+begin_src bash
./test_dryrun.sh          # runs every script with DRY_RUN=1 and fake paths
#+end_src

Nothing is written outside =/tmp= in dry-run mode; root actions are printed.
