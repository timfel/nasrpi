* nasrpi setup scripts

Run them in order, on the Pi; they escalate with ~sudo~ exactly where root is
needed (02 installs a Rust toolchain and builds =pizauth= as *you*, and asks for
your sudo password on a line of its own so a password prompt can't get eaten by a
pipe):

#+begin_src sh
./01_establish_mount_points.sh
./02_setup_pizauth_mbsync_sendmail.sh
./03_setup_smartmontools.sh
./04_setup_rclone.sh
./05_setup_backup.sh
#+end_src

Run any of them again any time: everything checks first, changes only what's
missing, and asks before touching anything. Shared helpers live in ~lib.sh~
(prompts, cron installer, package installer) — tweak there first.

** What each script does

*** 01 — Mount points

Puts your four disks into =/etc/fstab= (by UUID) at =/media/media=,
=/media/media_backup=, =/media/nas= and =/media/nas_backup=. Guides you through
picking disks by name/size, previews the fstab edit, and backs up fstab first.

*** 02 — pizauth, mbsync, sendmail

=pizauth= (<https://github.com/ltratt/pizauth>) is a small Rust daemon that owns
the OAuth2 tokens for your mail accounts and hands out access tokens on request.
mbsync and msmtp ask it for a token instead of ever knowing a password.

- Builds =pizauth= (pinned tag, =lto= build) into =/opt/pizauth= and installs a
  =/usr/local/bin/pizauth= wrapper that pins the socket to =/run/pizauth=, so the
  daemon, root's cron jobs and interactive shells all talk to the same instance.
  One systemd service, =pizauth=, started at boot.
- Adds your accounts to =/etc/pizauth.conf= (Gmail and Outlook presets built in,
  anything else prompted for). Existing =account= blocks are kept verbatim when
  you rerun; =awk~ reads them, no Python involved.
- OAuth sign-in opens a URL in *your laptop's* browser: 02 prints the link and
  waits while =pizauth= catches the redirect through an SSH tunnel you open from
  the laptop (=ssh -N -L 127.0.0.1:19024:127.0.0.1:19024 tim@think=). Nothing has
  to be pasted back, and no code or token is ever typed by hand.
- Keeps the tokens across reboots, *sealed to your LAN*: pizauth dumps its token
  state on every change and restores it when the server starts, but a pizauth dump
  is not encrypted (only obfuscated), so we always seal it with gpg. The key is
  derived from your router's UPnP device id (=uuid:...=, readable without a
  password only from inside your LAN) and is never stored on the Pi. A Pi booting
  somewhere else cannot derive it and stays unsigned; nothing unencrypted ever
  reaches the disk. =/etc/default/nasrpi-pizauth= holds the settings.
- Writes =/etc/mbsyncrc= (XOAUTH2 straight to the provider, =Sync Pull= only) and
  =/etc/msmtprc= (=auth xoauth2= with =passwordeval pizauth show <account>=),
  installs =/usr/sbin/sendmail= via ~msmtp-mta~, and a weekly mbsync cron job.
  Missing a sync is fine: if =/media/nas= is not mounted or =pizauth= is not
  answering, the run logs one line, exits 0 and next week's run catches up.
- Per-account choices (maildir folder, folder patterns, provider hosts) live in
  =/etc/nasrpi-mailmaps=. Gmail defaults to pulling only
  ="[Google Mail]/All Mail"=, which already contains inbox and sent mail; Outlook
  and everything else pull =*=.

*** 03 — smartmontools

- Installs smartmontools to monitor all disks *via =/dev/disk/by-uuid=*.
  Schedules short tests nightly and long tests weekly, but *never spins up
  spun-down disks* (=-d maint=).
- smartd sends alert mail itself; each alert also runs a =-M exec= handler:
  =/usr/local/bin/nasrpi-smartd-alert.sh=. The device is passed as an argument
  and the report arrives on stdin. The handler logs to
  =/var/log/nasrpi-smart-alert.log= and *unmounts the failing disk*
  (=AUTO_UNMOUNT= at its top).
- *Zero tolerance:* =-I 5 -I 187 -I 197 -I 198= sends mail and triggers the
  handler as soon as reallocated, uncorrected or pending sector counts change at
  all.

*** 04 — rclone

Installs rclone and runs ~rclone config~ so you can add remotes. Then installs a
weekly cron job that copies every remote into =/media/nas/<REMOTENAME>=. Skips
when =/media/nas= is unmounted.

*** 05 — Backup

Installs a weekly cron job running ~rsync -a --delete~ for two pairs:

- ~/media/nas/ → /media/nas_backup=~
- ~/media/media/ → /media/media_backup=~

Per pair it dry-runs first; if more than N% of destination files would be
deleted, it aborts that pair and *sends you a report*. Also mails on failure.
Skips a pair when either of its mounts is missing.

** Tweaking

- Cron schedules: rerun the script, or edit =/etc/cron.d/nasrpi-*= directly.
- Mail: =/etc/nasrpi-mailmaps= (=account=folder=, plus =provider=, =imap_host=,
  ~patterns~ per account) — edit it and rerun 02 to regenerate =/etc/mbsyncrc=
  and =/etc/msmtprc=.
- Token dump: =/etc/default/nasrpi-pizauth= (=DUMP_FILE=, =GATEWAY=, =UPNP_PORT=,
  callback port, ssh target). Rerun 02, or call the pieces directly:
  =/usr/local/bin/nasrpi-pizauth-key key= (what the derived key would be),
  =nasrpi-pizauth-dump= (seal a fresh dump), =nasrpi-pizauth-restore= (unseal and
  feed it back to pizauth).
- pizauth itself: =/etc/pizauth.conf= (accounts, callback port, notify/startup/dump
  commands), =sudo /usr/local/bin/pizauth status|show <account>|refresh=.
- Backup knobs (~NOTIFY_EMAIL~, ~DELETE_PCT~): top of
  =/usr/local/bin/nasrpi-backup.sh=.
- SMART alert behaviour: ~AUTO_UNMOUNT~ at the top of
  =/usr/local/bin/nasrpi-smartd-alert.sh= (set ~no~ for log/mail only); watched
  attributes are the =-I= list in =/etc/smartd.conf= (zero tolerance by default).
  Rerun 03 after adding or removing disks.
- Backup source/dest pairs: ~PAIRS~ at the top of
  =/usr/local/bin/nasrpi-backup.sh~ (one ~source dest~ line per pair).

** Notes / gotchas

- Needs Debian/Raspbian (~apt~) on the Pi; scripts exit cleanly elsewhere.
- Config source of truth for mail accounts: =/etc/pizauth.conf= in pizauth's own
  format, one =account "name" { ... }= block each with =client_id=,
  =client_secret=, =auth_uri=, =token_uri=, =scopes= and a =login_hint=. Add a
  block (or rerun 02 to be walked through it), then sign in:
  =sudo /usr/local/bin/pizauth show <account>= prints the URL if no token exists.
  =/etc/nasrpi-mailmaps= decides where each account's mail lands.
- =/usr/local/bin/pizauth= is a wrapper that sets =XDG_RUNTIME_DIR=/run/pizauth=
  and then runs =/opt/pizauth/bin/pizauth=. Use it everywhere (=sudo pizauth
  status= works) — the real binary without that environment looks for the socket
  somewhere else and reports "Not running".
- Tokens live in =/var/lib/pizauth= and must stay off =/media/nas=: that disk is
  world-readable-ish and gets rsynced and pushed to the cloud by 04/05.
- The sealed dump protects against a stolen SD card, not against someone standing
  in your LAN (they can read the router's device id too, or steal the router as
  well). That trade-off is what makes an unattended restore possible at all. If
  the key cannot be derived the dump simply stays sealed: pizauth comes back up
  without tokens and asks you to sign in.
- Replace the router, or turn its UPnP off, and the old dump can no longer be
  opened: rerun 02 to sign in once and reseal. A router that keeps the same
  =uuid:...= keeps the dump readable.
- Mail sync is pull-only on purpose (=Sync Pull=): this box is an archive, not a
  second IMAP server, so nothing can rename or delete anything upstream.
- Outgoing mail always goes through msmtp (=~/etc/msmtprc~, mode 600) via the
  ~sendmail~ shim from ~msmtp-mta~. Beware: a =~/.msmtprc~ would override the
  system config for that user.
- =libsasl2-modules-kdexoauth2= provides the XOAUTH2 mechanism mbsync needs.
- 05's safety net compares proposed deletions against each destination's file
  count; the first run against an empty destination deletes nothing.
- Migrating from the old Python =emailproxy= setup? Run
  =sudo ./cleanup_emailproxy.sh= once: it stops and disables that service, removes
  =/opt/emailproxy= (asking before deleting the OAuth state) and the superseded
  cron entry. Then rerun 02.

** Testing without the Pi

#+begin_src bash
./test_dryrun.sh          # every script with DRY_RUN=1 against fake paths
./test_pizauth_seal.sh    # the LAN-sealed token dump, for real, unprivileged
#+end_src

Nothing is written outside =/tmp= (or =.tmp/=) in dry-run mode; root is never
involved. The seal test runs the real helpers and gpg: it fakes a router by
feeding the UDN through =/etc/default/nasrpi-pizauth=, and a fake =pizauth=
binary for =dump=/=restore=.
